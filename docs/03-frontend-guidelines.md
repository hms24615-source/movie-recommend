# 03. 프런트엔드 구현 지침

## 범위
`index.html`, `src/css/styles.css`, `src/js/app.js`에서 단일 페이지 UI와 사용자 상호작용을 구현한다. 외부 프런트엔드 프레임워크는 사용하지 않는다.

## HTML 구성
- 헤더
- 영화 추천 입력 폼
- 추천 결과 영역(초기에는 숨기거나 안내 문구 표시)
- 비슷한 영화 목록
- 피드백 작성 폼
- 최신 피드백 목록
- 공통 상태 메시지 영역

각 영역에는 의미 있는 `id`를 부여하고 JS는 해당 요소를 선택해 동작시킨다. 입력에는 `label`, 폼에는 적절한 `button type="submit"`을 사용한다.

## 추천 입력 동작
- 입력 문장은 3~500자 범위로 제한한다.
- 앞뒤 공백을 제거하고 빈 값이면 요청하지 않는다.
- 제출 중 버튼을 비활성화하고 “추천을 찾는 중…” 상태를 표시한다.
- `POST /api/recommend`로 JSON 요청을 보낸다.
- 성공 응답은 검증된 필드만 DOM에 표시한다.
- 텍스트 렌더링은 `textContent` 또는 안전한 DOM 생성 방식을 사용한다. AI 응답을 `innerHTML`에 직접 넣지 않는다.
- 실패하면 사용자가 다시 시도할 수 있는 한국어 메시지를 보여준다.

## 영화 결과 표시
- 대표 추천: 제목, 개봉일, 러닝타임, 설명.
- 비슷한 영화: 0~3개.
- 개봉일이 없으면 “정보 확인 필요”, 러닝타임이 없으면 “정보 확인 필요”로 표시한다.
- 결과가 없거나 데이터 구조가 예상과 다르면 화면을 깨뜨리지 않고 오류 상태를 표시한다.

## 피드백 동작
- 이름은 선택, 0~30자. 본문은 필수, 1~500자.
- `POST /api/feedback`로 저장한다.
- 성공 시 입력 폼을 초기화하고 새 피드백을 목록 맨 위에 추가한다. 서버가 반환한 저장 결과를 사용한다.
- 페이지 초기화 시 `GET /api/feedback`으로 최신 피드백 최대 50개를 불러온다.
- 목록 렌더링은 이름·본문 모두 `textContent`를 사용한다.
- 빈 이름은 “익명”으로 표시한다.
- 작성 전 “등록한 피드백은 다른 방문자에게 공개됩니다.”를 안내한다.

## 오류 상태 문구 예시
- 입력 누락: “원하는 영화 분위기나 조건을 3자 이상 입력해 주세요.”
- 추천 실패: “추천을 가져오지 못했어요. 잠시 후 다시 시도해 주세요.”
- 피드백 실패: “피드백을 저장하지 못했어요. 입력 내용을 확인하고 다시 시도해 주세요.”
- 목록 조회 실패: “피드백을 불러오지 못했어요. 새로고침 후 다시 시도해 주세요.”

## 완료/검증 기준
- [ ] 추천 폼의 Enter/버튼 제출이 모두 작동한다.
- [ ] 제출 중 중복 요청이 방지된다.
- [ ] 성공 응답이 안전한 텍스트로 렌더링된다.
- [ ] 이름 없이 피드백을 전송할 수 있다.
- [ ] 피드백 저장 후 목록 최상단에 나타난다.
- [ ] 새로고침 후 저장된 피드백이 유지된다.
- [ ] 빈 목록·로딩·오류 상태가 구분된다.
- [ ] 320px 너비부터 데스크톱까지 레이아웃을 확인한다.
