# 04. 백엔드 및 AI 구현 지침

## 서버 API
Vercel Node.js Functions로 아래 엔드포인트를 만든다.

### `POST /api/recommend`
요청:
```json
{ "prompt": "비 오는 날 보기 좋은 따뜻한 영화를 추천해줘" }
```
성공 응답:
```json
{
  "recommendation": {
    "title": "영화 제목",
    "releaseDate": "YYYY 또는 YYYY-MM-DD",
    "runtimeMinutes": 120,
    "description": "짧은 설명"
  },
  "similarMovies": [
    {
      "title": "비슷한 영화 제목",
      "releaseDate": "YYYY",
      "runtimeMinutes": 110,
      "description": "짧은 설명"
    }
  ]
}
```
- `releaseDate`, `runtimeMinutes`는 확인할 수 없으면 `null` 허용.
- `similarMovies`는 배열이며 최대 3개.
- 서버는 요청 메서드, JSON 형식, 문자열 길이를 검사한다.
- OpenAI API 키는 서버 환경 변수에서만 읽는다.
- 모델명은 `OPENAI_MODEL`에서 읽는다.

### `GET /api/feedback`
- 최신순 `created_at DESC` 최대 50개 반환.
- 반환 필드는 `id`, `name`, `message`, `created_at`만 포함한다.

### `POST /api/feedback`
요청:
```json
{ "name": "선택 이름", "message": "서비스가 마음에 들어요." }
```
- 서버에서 길이·공백·타입을 재검증한 뒤 Supabase에 저장한다.
- 성공 시 저장된 행을 반환한다.

## AI 응답 제어
- 모델에 사용자의 조건에 맞는 영화 1편과 비슷한 영화 최대 3편을 요청한다.
- JSON Schema 또는 동등한 구조화 출력 기능을 사용해 필드 타입을 제한한다.
- 시스템 지침은 “확인할 수 없는 개봉일/러닝타임은 추측하지 말고 null로 반환”을 명시한다.
- 영화 제목과 설명은 추천 콘텐츠이며, 사실 정보는 별도 검증되지 않을 수 있음을 UI에 짧게 알린다.
- 서버에서 JSON 파싱 후 필수 필드·타입·배열 길이를 검증한다.
- 구조가 맞지 않으면 제한된 횟수만 재시도하거나 일반 오류를 반환한다. 무한 재시도 금지.
- 사용자 입력을 시스템 지침으로 취급하지 않는다. 프롬프트 인젝션에 의해 키·시스템 메시지·내부 설정을 노출하지 않도록 한다.

## 오류 응답 규격
```json
{ "error": { "code": "INVALID_INPUT", "message": "요청 내용을 확인해 주세요." } }
```
권장 상태 코드:
- 400: 잘못된 입력
- 405: 허용되지 않은 메서드
- 429: 요청 제한 초과
- 500: 서버 내부 오류
- 502: AI 제공자 응답 오류

브라우저에는 안전한 메시지만 전달한다. 원본 예외와 스택은 서버 로그에 제한적으로 기록하고 비밀 정보는 제거한다.

## 기본 보호 장치
- 본문 크기 제한(예: 10KB).
- 추천 입력 길이 3~500자.
- IP 또는 플랫폼이 제공하는 식별 정보를 활용한 기본 rate limit 검토. 신뢰할 수 없는 `X-Forwarded-For`를 무조건 신뢰하지 않는다.
- API 호출 비용을 통제할 수 있도록 토큰 출력량을 제한한다.
- 타임아웃과 실패 처리를 구현한다.

## 완료 기준
- [ ] 서버에서만 OpenAI API를 호출한다.
- [ ] 정상 응답이 정해진 JSON 스키마를 따른다.
- [ ] 알 수 없는 날짜·러닝타임은 `null`이다.
- [ ] 비슷한 영화는 최대 3편이고 중복이 없다.
- [ ] 잘못된 입력, 잘못된 메서드, AI 오류가 적절한 상태 코드로 응답한다.
- [ ] 브라우저 개발자 도구에서 API 키가 노출되지 않는다.
