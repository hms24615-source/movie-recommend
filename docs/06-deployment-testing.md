# 06. 배포 및 검증 지침

## 사전 준비
- OpenAI API 키와 사용할 수 있는 모델명
- Supabase 프로젝트
- Vercel 계정 및 Git 저장소
- Node.js LTS, npm, Vercel CLI

## Supabase 설정
1. Supabase 프로젝트를 생성한다.
2. SQL Editor에서 `docs/05-supabase-guidelines.md`의 SQL을 실행한다.
3. Project URL과 Service Role Key를 안전하게 복사한다.
4. 테이블 생성 및 RLS 활성화 여부를 확인한다.

## 로컬 실행
1. 의존성을 설치한다: `npm install`
2. `.env.example`을 참고해 `.env.local`을 만들고 실제 환경 변수를 채운다.
3. Vercel CLI를 준비하고 `vercel dev`로 실행한다.
4. 브라우저에서 로컬 주소를 열고 추천 및 피드백 흐름을 테스트한다.
5. 환경 변수 변경 후에는 개발 서버를 재시작한다.

## Vercel 배포
1. Git 저장소를 Vercel 프로젝트에 연결한다.
2. 프로젝트 설정의 Environment Variables에 아래 값을 등록한다.
   - `OPENAI_API_KEY`
   - `OPENAI_MODEL`
   - `SUPABASE_URL`
   - `SUPABASE_SERVICE_ROLE_KEY`
3. Preview와 Production 환경에 필요한 값을 각각 설정한다.
4. 배포 후 `/api/recommend`, `/api/feedback`를 실제 도메인에서 확인한다.
5. 배포 로그에 비밀 값이 출력되지 않는지 확인한다.

## 수동 기능 테스트
| ID | 시나리오 | 기대 결과 |
|---|---|---|
| T01 | “비 오는 날 볼 따뜻한 영화” 입력 | 영화 추천 정보가 표시됨 |
| T02 | 입력 없이 제출 | 입력 안내, API 호출 없음 |
| T03 | 2자 입력 | 최소 길이 안내 |
| T04 | 추천 중 버튼 재클릭 | 중복 요청 방지 |
| T05 | AI가 날짜를 모르는 영화 | 날짜를 추측하지 않고 “정보 확인 필요” |
| T06 | 유사 영화 응답 4개 모의 | 최대 3개만 표시 |
| T07 | 이름 없이 피드백 등록 | 익명으로 저장·표시 |
| T08 | 501자 피드백 | 저장 거부 및 안내 |
| T09 | HTML 태그가 포함된 피드백 | 태그 실행 없이 문자 그대로 표시 |
| T10 | 피드백 등록 후 새로고침 | 저장 내용 유지 |
| T11 | Supabase 연결 실패 | 친절한 오류 표시, 앱 전체는 유지 |
| T12 | 모바일 320px 화면 | 가로 스크롤 없이 사용 가능 |

## 개발자 검증
에이전트는 프로젝트에 실제 존재하는 스크립트에 맞춰 실행한다. 존재하지 않는 테스트 명령을 성공했다고 보고하지 않는다.
- 문법 검사: JS 파일별 `node --check` 등 가능한 검사 실행
- 정적 확인: HTML 구조, 누락된 요소 ID, 콘솔 오류 확인
- API 확인: 정상/잘못된 입력/서버 오류 응답 확인
- 보안 확인: 브라우저 소스와 네트워크 응답에 서버 키가 없는지 확인
- 반응형 확인: 320px, 768px, 1440px 폭에서 확인

## 최종 완료 체크리스트
- [ ] 모든 PRD 기능 요구사항이 동작한다.
- [ ] 피드백은 로그인 없이 저장되고 모든 사용자에게 최신순 공개된다.
- [ ] 추천 정보의 불확실성을 사용자에게 숨기지 않는다.
- [ ] 오류·로딩·빈 상태가 구현되어 있다.
- [ ] 환경 변수와 비밀 키 관리가 안전하다.
- [ ] 모바일과 데스크톱 검증을 완료했다.
- [ ] 실제 수행한 검증 결과와 남은 작업을 보고했다.

## 외부 설정이 필요한 항목
OpenAI 키 발급, Supabase 프로젝트/SQL 설정, Vercel 프로젝트 연결과 환경 변수 등록은 계정 소유자가 직접 수행해야 한다. 에이전트는 권한이 제공되지 않은 계정 작업을 완료했다고 주장하지 않는다.
